# CR047 — Consistent Character Daily Memory Tool Retrieval

_Status: Merged into local staging._

## 1. Purpose

Make the Chat and Character Briefing `search_character_daily_memories` tools
use the same Character Daily Memory retrieval behavior as Memories-tab Preview.
The current briefing trace can return no memories when Preview finds eligible
records, so the tool adapters need one retrieval boundary, policy, and scope.

## 2. Goals

- Use the existing Memories-tab retrieval settings as the single policy for
  Preview, Chat, and Character Briefing, including semantic, importance,
  recency, and minimum-rank settings.
- Keep the owning character's Daily Memory corpus, active-run filtering,
  embedding-space validation, ranking, thresholding, and result selection
  identical across those callers.
- Preserve caller-specific query construction:
  - Chat uses the last configured `N` visible messages as its query.
  - Character Briefing uses the dedicated natural-language query generated by
    its LLM tool call.
  - Preview continues to use its selected Conversation's last configured `N`
    visible messages.
- Keep retrieval policy host-controlled. The model-facing tool accepts only a
  query and cannot choose weights, thresholds, limits, or scope.
- Keep legacy `extensions.characterMemories` and Scene summaries outside this
  contract.

## 3. Explicit amendment to the prior implementation

The earlier CR047 implementation added Character Daily Memory retrieval and
prompt injection to `prepareConversationPromptHistory`, with a corresponding
`dailyMemoryBlock` return value and insertion in `generate.routes.ts`. That
boundary is outside this request and must be removed/reverted. The corrected
implementation must not:

- retrieve Daily Memories while preparing ordinary Conversation prompt history;
- inject a Daily Memory system block into `finalMessages`;
- add a Chat adapter, query derivation, or retrieval dependency to
  `conversation-history-runtime.ts` or its `generate.routes.ts` call site.

The Chat path to preserve is the existing custom
`search_character_daily_memories` tool path. Its host callback should continue
to derive the query from the last configured `N` visible messages, then call
the shared retrieval service.

## 4. Proposed solution

Use `createCharacterDailyMemoryRetrievalService().searchForCharacter()` in
`packages/server/src/services/character-daily-memories/retrieval.service.ts`
as the sole server-side retrieval boundary. It loads the owning character's
persisted settings, active Daily Memory rows, and configured embedding source,
then applies the shared ranking and minimum-rank threshold. Remove any
caller-specific cap; there is no persisted result-limit setting, so all
records meeting the configured threshold remain eligible.

Keep the existing Preview route adapter in
`routes/character-daily-memories.routes.ts` on that service and preserve its
response shape. Keep the existing Chat tool host callback and change only its
retrieval wiring/query preparation as needed so it uses the same service and
settings. Keep Character Briefing's
`search_character_daily_memories` callback in
`services/character-briefing.service.ts`; the briefing LLM continues to
generate the query and the host supplies the owning character ID.

Normalize missing or malformed persisted settings once at the shared service
boundary using existing Character Daily Memory defaults. Preserve the existing
unavailable/empty-result behavior when settings, embeddings, or the retrieval
backend are unavailable. Do not use the generic `memory-recall` corpus for
this feature.

## 5. Invariants and boundaries

- Equivalent queries for the same owning character produce identical eligible
  records, order, threshold behavior, and count in Preview, Chat, and Briefing.
- Query construction is caller-specific; retrieval policy, corpus, and scope
  are not.
- The tool cannot override persisted weights, threshold, result selection,
  character scope, or corpus.
- No Daily Memory retrieval or prompt injection occurs in
  `prepareConversationPromptHistory`.
- Legacy `extensions.characterMemories` / Scene summaries are never read by
  this retrieval service.
- Missing/disabled retrieval, empty queries, empty corpora, and unavailable or
  mismatched embedding sources retain structured safe-degradation behavior.

## 6. Risks and mitigations

- **Tool adapters may have drifted.** Route Chat and Briefing through the same
  retrieval service and add parity fixtures with equivalent queries.
- **Persisted settings may be absent or invalid.** Normalize at the shared
  boundary and retain existing defaults.
- **The generated Briefing query differs from Chat's message query.** This is
  intentional; parity tests use equivalent fixture queries while separate
  tests assert each caller's query source.
- **A prior implementation changed Conversation prompt assembly.** Remove the
  `prepareConversationPromptHistory` Daily Memory additions and test that
  normal Conversation prompt assembly remains unchanged.

## 7. Validation expectations

- Server tests prove Preview, Chat, and Briefing invoke the same retrieval
  boundary and return identical ranked fixture results for equivalent queries.
- Tests cover persisted weights, recency, minimum rank, character scope,
  active-memory filtering, no implicit result cap, empty results, unavailable
  embeddings, and malformed/default settings.
- Chat tests prove only the last configured `N` visible messages form its query;
  hidden and non-visible messages are excluded.
- Briefing tests prove the query remains LLM-generated and the tool schema is
  query-only.
- Regression tests prove `prepareConversationPromptHistory` does not retrieve
  or inject Character Daily Memories.
- Run proportionate server checks and the staging production build. Focused
  Playwright coverage is not required by the current agreement.
